- 2026-09-06: Sampling defaults, decisions from the adversarial security and code reviews of the branch. (1) The pinned server checks sampling in two places and the first range table had read only one: mlx_lm.sample_utils.apply_top_k refuses a top-k at or above the model's vocabulary size and raises inside generation, so an oversized default leaves the process healthy and fails every request that omits top-k. Gropius cannot know a vocabulary size at save time, so top-k is capped at 1024 — far below the smallest vocabulary an MLX model ships, and above any top-k that changes an outcome. The range test is now two tests, one for "never wider than the server's" and one pinning the exact bounds, so a deliberate narrowing is visible instead of hidden inside an equality. (2) The settings endpoint's "keep what you did not send" rule applies to fields, not to the members of a collection: naming model_sampling replaces the set (otherwise a removed override came back, because encoding/json merges into an existing map), while omitting it still keeps what is there. (3) Per-model overrides are capped at 256 and the settings body at MaxConfigBytes, because everything saved lands in config.json and a config.json too large to read sends the next start into the fail-closed loopback-only branch. (4) Case-variant override keys are refused at the endpoint (the file path already dropped them) and the lookup iterates in sorted order, so no map can make one model load at different temperatures. (5) Temperature and max-tokens keep the server's own unbounded ranges: an extreme value there produces poor output or a long generation, not a failure, and any ceiling would refuse a value the server accepts and serves.

- 2026-09-06: Per-model settings that are not sampling parameters live in `config.Config.PerModel`, a map keyed by the registry's canonical repo id whose value is a `config.ModelSettings` struct, holding the system-message-merging switch (spc-2609061822383838). It sits beside `ModelSampling` rather than absorbing it: spc-2609061822383838 proposed one per-model structure for both records, but the sampling-defaults branch landed first with its own `model_sampling` map and a `Sampling` value type of its own, and merging the two afterwards would have rewritten a shipped settings file's shape for tidiness rather than for a user. The two maps are therefore held to the same rules instead — keyed by canonical repo id, bounded by one ceiling (`MaxPerModel = MaxModelSampling`), sanitised on load with what was dropped reported to the log, and replaced rather than merged into when a settings form names them, because `encoding/json` merges into an existing map and leaving an entry out is the only way a form can remove one. Keys are case-folded to the registry's spelling, because that spelling is the id a request resolves to; the gateway looks the map up by exact id, once per request. Merging itself is confined to `internal/gateway/systemmerge.go`, the only file allowed to name a chat message's fields or the constants for them, held there by `internal/archtest`, so a second reader of prompt content cannot appear without a diff that says so (adr-2609061610102325).
- 2026-09-06: System-message merging folds a request's instructions into the conversation's own leading system message — that message rebuilt from its own fields with only its content replaced by the join — so a `name`, a cache directive or anything else the client attached to it stays on the message that owned it and no authorship is invented. A system message that is not the leading one must carry `role` and `content` alone: its text is appended to another message, and a field on it would have to be dropped or reattributed, neither of which the gateway gets to decide, so such a request is relayed unchanged. Settled after the first cut refused any system message carrying an extra field at all, which was safe but did nothing for the clients the feature exists to serve. Empty instructions contribute nothing to the join rather than a blank line at the front of the prompt; content that is JSON null, a list of parts, or bytes that are not valid UTF-8 is relayed rather than rewritten, because Go's string decoding would repair invalid bytes into characters the client never sent. Two details come from running it rather than reading it, and both produce a false green rather than a failure. `grep -v` with a bare hyphen pattern is refused outright by at least one grep people install over the system one; it exits 2 with a usage message, which `|| true` swallows under `set -euo pipefail`, so the filter matches nothing, the election is wrong in exactly the case the filter exists for, and every test still passes. The filter is therefore the shell's own `case` and depends on no external binary. Separately, accumulating a newline-separated list inside an indented block scalar folds that indentation into the values, so `sort -V` ranks tags carrying leading spaces and the equality test that reads the result can never match — code that looks correct and produces a comparison with no true case. The reconsideration condition is a tag that carries a hyphen for some reason other than a pre-release — a build or platform suffix — which this rule would silently withhold from the latest pointer.
