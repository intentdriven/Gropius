- 2026-08-02: Automated bug-hunt round 8: the gateway no longer relays a model-launch failure's raw error to the network — Launcher.Launch failures (which can embed absolute local paths: the venv interpreter, the model directory, a log file) now wrap a new runtime.LaunchError that the gateway matches on to log server-side and answer with a generic message, while other pool errors (memory budget, busy) still reach the client verbatim; evictForLocked no longer picks a still-loading model as an eviction victim (a caller giving up mid-load was dropping inFlight to 0 while the load kept running, and the missing isReady guard — present on reapIdle but not here — could livelock the pool under memory pressure with short client timeouts); the no-absolute-paths-in-docs pre-commit hook now filters matches individually instead of whole lines, so a private path sharing a line with the exempted /Users/Shared/ path is no longer silently waved through. - 2026-08-02: Automated bug-hunt round 9: Registry.Rescan no longer drops a model from the index on a non-ENOENT stat error (a permission hiccup or transient I/O error on its directory was being treated as proof of deletion, contradicting the code's own "distinguish gone from incomplete" intent; only a confirmed fs.ErrNotExist now counts as gone); Pool.startLocked now calls a new Launcher.Precheck before evicting a resident victim to make room, so a launch failure that strikes moments later (a missing venv, or the new model's own directory vanishing in a race with a concurrent delete) no longer destroys an unrelated, healthy model for zero benefit — eviction is not reversible; /api/search's limit query parameter is now capped, closing an unbounded outbound-request amplification lever reachable even from a blind, Origin-less cross-origin GET. Refuted: handleUnload's uniform 409 for a not-loaded model (repeat of round 5's explicit refutation — ErrNotLoaded reflects pool residency, not registry existence, so 409 is correct and 404 would conflate the two) and a README pitch-text wording difference from the internal IDENTITY.md reference (the file's own practice treats only the one-line tagline as verbatim-shared; the longer pitch is deliberately paraphrased per surface, predates IDENTITY.md, and was never in sync with it).
- 2026-08-03: Automated bug-hunt round 10: the gateway's non-streaming completion relay no longer buffers an unbounded upstream response (max_tokens/logprobs are client-controlled and unbounded, so a well-behaved mlx_lm.server could still be driven to a very large single JSON object; a new maxResponseBody cap on relayRewritingModel's json branch mirrors the existing maxRequestBody cap on the request side); hub.apiError now reads the captured error body with io.ReadAll(io.LimitReader(...)) instead of a single Read call, which per the io.Reader contract could truncate the message well before its intended 512-byte budget on a body delivered across several small reads. Deferred to the ledger rather than auto-patched: a misleading "Server running in another account" client-mode menu string that, per iss-5's own analysis, can only currently mean a same-account relaunch (noted on iss-5, to be resolved alongside its redesign rather than reworded twice); a genuine data race in the vendored brutella/dnssd library between Advertiser.refresh's UpdateText and the running mDNS responder, confirmed by reading the library source directly, whose only in-repo fix trades an in-place TXT update for a full withdraw/reannounce cycle (new iss-12); and go.mod's module path (github.com/intentdriven/Gropius) not matching the repository's actual location (REPPL/Gropius), latent today but requiring a large mechanical import-path rename across 19 files to fix properly (new iss-13). Refuted: a hub downloadFile size-cap gap (split verdict — technically accurate but not a distinct risk beyond the already-accepted unbounded-download-size design, discarded per the round's split-verdict convention) and a runtime pidLedger EPERM/ESRCH-conflation claim (unreachable — the ledger file's 0600 mode and the shared root's sticky bit block a peer account from ever reading or deleting another account's entries first, the same mechanism iss-10 already documents for registry.json/config.json).
- 2026-08-05: Automated bug-hunt round 12: the archtest GUI-toolkit scan now enumerates internal packages with a wildcard instead of a hand-kept root list that had drifted (internal/mlxtest was entirely unscanned — a planted systray import passed the old test — and internal/capability was covered only through one transitive import); advertised mDNS names are clamped to the 63-octet DNS label limit (macOS permits 63-character LocalHostNames, dnssd validates characters but not length, and its transport silently drops messages that fail to pack, so a 54-plus-character name killed advertising while every layer logged success); distinct repo ids can no longer share a model log file (flattening the slash to an underscore collided a/b_c with a_b/c, and Launch's O_TRUNC then truncated the first model's live log; HuggingFace forbids underscores in namespaces, so the collision is reachable only via sideloaded directories); the getting-started install step now flags its firewall password prompt as the shared-install step already did; a hostname example respelled to the Alice persona. - 2026-08-05: Automated bug-hunt round 13: the gateway's loopback exemption from the API key now also requires a loopback Origin when one is present and a key is configured, closing a CSRF-class bypass — a webpage the user's browser visits also connects from 127.0.0.1, so a no-preflight cross-origin POST (a CORS-safelisted Content-Type needs no Authorization header) rode the exemption straight through /v1/chat/completions even with a key configured, the same class of attack the control plane's loopbackOnly already blocked; the check is gated on apiKey != "" (a merge-gate correctness review caught the first version applying it unconditionally, which narrowed the intentionally open no-key default's loopback behaviour — with no key configured there is no CSRF-defeated key to protect, so that mode is now provably untouched, pinned by a new test). Registry.Remove now broadcasts its in-memory deletion unconditionally, like every other mutator in the file, instead of skipping the notification on a saveLocked or os.RemoveAll failure (the only production subscriber already re-polls live state every 2s, so this was undetectable in the UI, but the code asymmetry was real). - 2026-08-05: Automated bug-hunt round 14: internal/app's readCapped (backing validateModelDir) now opens config.json with O_NONBLOCK|O_NOFOLLOW plus an fstat regular-file check, mirroring registry.go's readManifest — a model directory adopted as ready from another account in shared-cache mode keeps that account free to replace its own config.json with a FIFO or symlink at any time (the shared root's sticky bit only blocks a non-owner from doing so), and a later retry's restoreReady call would otherwise block forever on the FIFO (wedging App.Close's dlWG.Wait) or follow the symlink with this account's privileges; archtest's GUI-toolkit scan now passes -test to its `go list -deps` invocation, since the plain form only walks a package's non-test import graph and would miss a GUI-toolkit import confined to an internal package's own _test.go file, a blind spot distinct from round 12's stale-root-list fix. Refuted: a repeat of the round-5/7/13 control-plane MaxBytesReader finding (found independently by one hunt sweep, split verdict, discarded as the same accepted every-loopback-caller-is-the-administrator design); an unescaped repo-ID splice into hub.Files/RepoSize's URL from HuggingFace search results (defense-in-depth only — HuggingFace's own search API is the only source, over HTTPS, with no realistic attacker-controlled path); and config.Load's plain os.ReadFile lacking O_NOFOLLOW (real but capped at the same LAN-exposed-no-auth default already tracked as iss-1, so not worth a dedicated fix this round).

- 2026-09-06: The models list publishes each model's architectural context length, read from the model's own `config.json`: `max_position_embeddings` at the top level, falling back to `text_config.max_position_embeddings` for multimodal and composite configurations, with no scaling arithmetic applied and a ceiling of 8,388,608 tokens above which the figure is refused. The key rule was sampled against eleven configurations (the four benchmarked models and the lab Mac's cache) and recorded in the 2026-09-06 model-bench findings note. The registry owns the only decoder of a model's `config.json`, and the app layer's download paths read the figure through its exported primitive, so the rescan and the download path cannot drift apart.
