      Eviction grace
      
      
Off unless you turn it on. While it is off, a request for a model
        that does not fit unloads the least recently used idle model straight away, even
        one that answered a moment ago — which on a Mac two people share means their
        models take turns evicting each other between turns. While it is on, that request
        waits instead: for a model to have been idle for the protection below, or for its
        own wait to have passed that long, whichever comes first. If nothing frees up
        within the maximum, the request gets the same refusal it would have had at once,
        now saying how long it waited. With an API key set above, every answer that
        reached a model server also says whether it waited and for how long, in the
        X-Gropius-State and X-Gropius-Queue-Time headers; a
        server with no key sends them to nobody, the same rule the models list applies
        to which models are loaded. The protection may not be longer than the idle
        timeout above when one is set, or the idle timeout would unload the very model
        a wait is protecting — and because that timeout only changes at a restart, a
        longer protection saved beside a raised timeout is held to the timeout still in
        force until you restart.

      
      
      

    


    
    

    

      Which models can chat
      
Each model carries the words HuggingFace puts on it — a pipeline
        tag such as text-generation, and tags such as
        conversational — recorded when it was downloaded. This rule decides
        which of them the models list marks as able to hold a conversation, so a chat
        client can leave an OCR or a speech model out of its picker. It filters nothing:
        every model stays callable over the API by name, whatever the rule says of it.
        Clear a field to stop testing that half; clear both and every model is marked as
        able to chat. A model downloaded before Gropius recorded these words, or while
        HuggingFace could not be reached, carries none and is marked as unable — download
        it again to give it the words.

      
      
    


    

      Sampling defaults
      
Served to every request that leaves the parameter out. A request
        that sets its own value always wins. A blank field means the model server's own
        default, shown in grey. A change reaches a model the next time it loads.

      
      
      
      
      
    


    

      Per-model sampling
      
One model can want a different figure. A field left blank here
        keeps the machine-wide default above.

      

      
      
      
      
      
      
      
    


    

      Request statistics
      
      
Off unless you turn it on. While it is on, Gropius records, for each
        request it serves: the model, when the request arrived, how it ended, whether it
        streamed, how many tokens went in and came out, how long the first token took, how
        long the whole request took, and how long it waited for the model. It never records
        a prompt, an answer, an API key or the address of the client that sent it, and
        nothing recorded leaves this Mac. Turning it off again empties the live view and stops
        new records; the records already kept on this Mac stay until you clear them.
        Everyone who can open this panel can turn it on and read it, which on a Mac that
        several people log into means every account on it — so on a shared Mac this is a
        decision for all of them, and while it is on Recording appears
        beside the server status at the top of this page. The
        what
        is recorded page says all of this field by field.

      
      
      
Records are kept in plain text files, one line of JSON each, under your
        own Gropius data folder. The size limit is the one that always wins, and the months
        figure clears out what fits within it. Whole files are removed at a time, oldest
        first, as records arrive and whenever you change either figure, so a limit you
        lower here takes effect when you save it. Switching recording off stops new records
        and leaves these ones where they are; Clear records is what removes
        them.

      

      
    


    

      Merge system messages
      
Some models refuse a conversation whose instructions are not all at
        the top, so an assistant that repeats its instructions mid-conversation gets an
        error instead of an answer. Switch merging on for such a model and Gropius gathers
        that request's instruction messages into the leading one, separated by a blank
        line, before the model sees it. Gropius reads the instruction messages of requests
        to that model and nothing else, keeps none of what it reads, and writes none of it
        down.

      

    


    

      Served context
      
The context window Gropius serves each model at, in tokens. Leave a
        field blank to serve the window the model itself declares. A request whose prompt
        and answer are estimated to be larger is refused, and the memory budget charges
        the cache this window costs — so lowering it is how a long-context model is made
        to fit a Mac that will not hold it at its full window.

      

    


    

      Pinned models
      
A pinned model stays in memory: Gropius never unloads it to make
        room for another, and the idle timeout above does not touch it. A request for a
        model that would need its memory is refused instead, so pin only the models you
        want protected. Pinning is not preloading — a pinned model is not loaded at
        start-up, it is protected from the moment something loads it.
